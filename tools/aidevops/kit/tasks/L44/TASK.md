# L44 — Веса модели: safetensors, pinned revision и sha256

**Направление:** 11 models.

## Сценарий
Init-контейнер скачивает модель по имени и ветке main и проверяет только, что файлы на месте. Так в кластер попадает любой коммит из репозитория модели, включая pickle-файлы, которые исполняют код при загрузке. Перед стартом inference проверь манифест: revision — полный commit sha, только безопасные форматы, пути внутри каталога модели, sha256 каждого файла совпадает.

## Контракт
```python
manifest = {
    "repo": "Qwen/Qwen2.5-1.5B-Instruct",
    "revision": "<полный sha коммита, 40 hex>",   # не "main"
    "files": {"model.safetensors": "<sha256>", "config.json": "<sha256>", "tokenizer.json": "<sha256>"},
}
verify(manifest, "/models/qwen")   # -> [Path(...), ...] в порядке имён
```

- Разрешены `.safetensors`, `.json`, `.txt`. Форматы на pickle (`.bin`, `.pt`, `.pth`, `.pkl`, `.ckpt`) запрещены: `torch.load` такого файла может выполнить произвольный код.
- `revision` — полный sha коммита. Ветка или тег могут сдвинуться, и та же конфигурация завтра скачает другие веса.
- Имена файлов из манифеста не должны выводить за каталог модели (`../`, абсолютные пути).
- Хэш считается потоково, кусками: веса весят гигабайты.

## Требования к результату
verify(manifest, root) возвращает проверенные пути; ValueError для revision не-sha и несовпадения sha256; PermissionError для .bin/.pt/.pkl/.ckpt и путей с ../; FileNotFoundError для отсутствующего файла.

## Как работать
```bash
./ai-lab start L44
# отредактируйте файлы workspaces/L44/
./ai-lab check L44
# при необходимости: ./ai-lab solve L44; ./ai-lab reset L44
```

**В production:** манифест кладут в Git рядом с Helm values, init-контейнер запускает проверку до старта vLLM, а веса хранят в своём S3 или registry (OCI-артефакт), а не тянут из интернета при каждом старте пода.

**Портфолио:** после успешной проверки приложи решение, вывод `check` и объяснение архитектурных решений. Не публикуй реальные ключи и логи с приватными данными.
