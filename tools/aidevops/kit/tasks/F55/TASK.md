# F55 — AI firewall: конвейер гвардов вокруг LLM с fail-closed и аудитом

**Направление:** 13 aisec. **После:** F50.

## Сценарий
Гварды, маскирование и аудит написаны по отдельности, а склеены в шлюзе как попало: маскирование до детектора КТ (он больше не видит данных), исключение в гварде пропускает запрос, в аудит пишется сырой промпт. Собери AI firewall: фиксированный порядок шагов, fail-closed, модель видит только маскированный текст, аудит без PII.

## Контракт
```python
fw = Firewall(input_guards=[kt_guard, injection_guard], output_guards=[exfil_guard],
              vault_factory=Vault, llm=call_model, audit=events.append)
fw.handle("req-1", "Напиши письмо ivan@corp.ru")
# {"status": 200, "text": "...ivan@corp.ru..."}
# {"status": 403, "reason": "kt"}           — гвард вернул block
# {"status": 503, "reason": "guard_error"}  — гвард упал
# {"status": 502, "reason": "upstream"}     — модель упала
```

Гвард — функция `text -> {"name": "kt", "verdict": "allow" | "flag" | "block"}`. `vault_factory()` создаёт объект с `mask` и `unmask` (F50) — новый на каждый запрос.

Порядок:
1. Входные гварды на **исходном** тексте: детектору КТ и секретов нужны реальные данные.
2. `mask` → `llm(masked)`: модель не видит PII.
3. Выходные гварды на ответе модели **до** демаскирования: им PII не нужны.
4. `unmask` → ответ клиенту.

- `block` любого гварда — сразу отказ с `reason` = имя гварда; модель не вызывается (для входных) или текст не отдаётся (для выходных).
- Исключение в гварде — `503 guard_error` (fail-closed): лучше отказать, чем пропустить непроверенное.
- Исключение модели — `502 upstream`.
- `flag` не останавливает запрос, но попадает в аудит.
- Ровно одно audit-событие на запрос: `request_id`, `status`, `verdicts` (`{имя: вердикт}`); без промпта, ответа и PII.

## Требования к результату
Входные гварды на исходном тексте до маскирования; block -> 403 без вызова модели; исключение гварда -> 503 fail-closed; модель получает только маскированный текст; выходные гварды на ответе до демаскирования; ошибка модели -> 502; flag пропускает, но попадает в аудит; одно audit-событие на запрос без исходных данных.

**В production:** этот конвейер — custom guardrail LiteLLM (`pre_call`, `post_call`) или отдельный сервис перед шлюзом (Envoy ext_proc). Fail-closed согласуй с ИБ и владельцами сервисов заранее: при падении гварда пользователи увидят 503, это нужно отражать в SLO и мониторинге (W66).
