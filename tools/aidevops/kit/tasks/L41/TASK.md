# L41 — LLM gateway: квота запросов и бюджет токенов

**Направление:** 11 models.

## Сценарий
Шлюз перед LLM-провайдером пропускает всё подряд: одна команда за час съедает дневной бюджет токенов и упирается в лимит провайдера для всех. Добавь на каждого tenant token bucket по запросам в минуту и суточный бюджет токенов с резервированием max_tokens до вызова модели и возвратом неиспользованного остатка после.

## Контракт
```python
gw = Gateway({"team-a": {"rpm": 60, "daily_tokens": 200000}})
gw.admit("team-a", max_tokens=800, now=time.time())
# {"status": 200, "reserved": 800}
# {"status": 429, "reason": "rate",   "retry_after": 1}      # секунд до следующего запроса
# {"status": 429, "reason": "budget", "retry_after": 41230}  # секунд до 00:00 UTC
# {"status": 403, "reason": "tenant"}
# {"status": 400, "reason": "max_tokens"}
gw.settle("team-a", reserved=800, used=312, now=time.time())  # вернуть 488 токенов в бюджет
```

- Token bucket: ёмкость `rpm`, пополнение `rpm / 60` запросов в секунду.
- Бюджет резервирует `max_tokens` при admit: фактический расход ещё неизвестен, а ответ модели может быть длинным.
- Отказ по бюджету не тратит квоту запросов.
- `now` передаётся явно — так шлюз тестируется без `sleep`.

## Требования к результату
admit(tenant, max_tokens, now) возвращает 200 / 429 rate / 429 budget с retry_after / 403 для неизвестного tenant / 400 для max_tokens <= 0; tenant-ы изолированы; settle() возвращает неиспользованный резерв; бюджет сбрасывается в новые сутки UTC.

## Как работать
```bash
./ai-lab start L41
# отредактируйте файлы workspaces/L41/
./ai-lab check L41
# при необходимости: ./ai-lab solve L41; ./ai-lab reset L41
```

**В production:** тот же учёт держат в Redis или в самом gateway (LiteLLM, Envoy AI Gateway, Kong AI), а `retry_after` отдают заголовком `Retry-After`. Клиенты из A18 должны его уважать.

**Портфолио:** после успешной проверки приложи решение, вывод `check` и объяснение архитектурных решений. Не публикуй реальные ключи и логи с приватными данными.
